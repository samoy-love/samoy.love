# samoy.love — дизайн-документ

Личная страница Алексея Самойлова — Teamlead продуктовой команды (10 человек) в Почте Mail.ru, в прошлом Backend-разработчик. Страница — одновременно **личная визитка, игровое резюме, вау-сайт и хаб проектов**: рабочие кейсы + fun-pet-проекты. Общий эффект: «этот человек много сделал и много умеет».

Статус: утверждено · Язык: русский · Дата: 2026-08-01

---

## 1. Концепция

**«Игровое резюме» в эстетике engineering-luxe.** Алексей делает игры в свободное время (Snakes с системой ачивок, игровой лаунчер ChillHub) — поэтому карьера подаётся как прокачка персонажа: путь Школа → Универ → Backend → Teamlead — это **level-путь**, рабочие проекты — **основной квест**, pet-проекты — **сайд-квесты**, а факты и заслуги — **ачивки**, которые «анлокаются» по мере скролла.

Критично: это **не мультяшная геймификация**, а дорогая, тёмная инженерная эстетика (Linear/Vercel-уровень) с игровой *структурой подачи*. Пиксель-арта и полосок здоровья нет; есть моноширинные ярлыки, тонкое свечение, метрики и иконки-ачивки в едином строгом стиле.

**Формула «вау + структура»**: движение и 3D-глубина живут *внутри* элементов (3D-фон hero, зажигающиеся вехи таймлайна, наклон карточек), а скелет страницы — неподвижная предсказуемая сетка. Пользователь всегда понимает, где он; «вау» никогда не ломает ориентацию. Три Z-слоя: фон-сцена → контент → hover-подъёмы.

## 3. Стек и технологии (mid-2026)

- **Astro 7** — статика, нулевой JS по умолчанию. Клиентский код — обычные `<script>` в компонентах, фреймворковых островов нет вовсе.
- **CSS scroll-driven animations** (`animation-timeline: view()`) — рисование линии таймлайна, заполнение полосы опыта и reveal секций **без JS**.
- **3D-сцена в hero на OGL** — минималистичная WebGL-библиотека (~14 КБ gzip; three.js сознательно нет — ~150 КБ). Единственный тяжёлый остров, грузится динамическим `import()` только на Full-уровне.
- **CSS-фичи 2026**: container queries, `:has()`, `color-mix()` в OKLCH, `text-wrap: balance`, `@property` для анимируемых градиентов, нативная вложенность.
- **Шрифты**: variable-шрифты, subset кириллица+латиница, `font-display: swap`, self-hosted.
  - Заголовки/текст: **Inter Variable**, латиница и кириллица в preload.
  - Акценты/метрики/код: **JetBrains Mono Variable**.
- Никаких: React, jQuery-подобных библиотек, CSS-фреймворков, аналитических скриптов третьих сторон.

## 4. Дизайн-система

### 4.1 Палитра (OKLCH)

| Токен | Значение | Роль |
|---|---|---|
| `--bg` | `oklch(0.13 0.015 260)` | Фон — глубокий сине-графитовый, не чёрный |
| `--bg-raise` | `oklch(0.17 0.02 260)` | Карточки, поверхности |
| `--text` | `oklch(0.93 0.01 260)` | Основной текст |
| `--text-dim` | `oklch(0.68 0.015 260)` | Вторичный текст |
| `--accent` | `oklch(0.78 0.16 195)` | Электрик-циан — ссылки, свечение, «анлок» ачивок |
| `--accent-warm` | `oklch(0.75 0.15 55)` | Тёплый янтарь — второй акцент, редкие ачивки |
| `--line` | `color-mix(in oklch, var(--text) 12%, transparent)` | Границы, разделители |

У каждого проекта — свой акцентный цвет карточки (задаётся в JSON): ChillHub — циан, Метро — розовый (Hello Kitty!), Snakes — лаймовый; рабочие проекты — в фирменной гамме синего Mail.

### 4.2 Типографика

- Шкала: `clamp()`-флюидная. H1 `clamp(2.6rem, 8vw, 5.5rem)`, вес 700→850 по variable-оси.
- Моно-акценты: секционные ярлыки в стиле `// 02 — основной квест`, статы, метрики, стек-теги.
- `text-wrap: balance` на заголовках, `max-width: 68ch` на тексте.

### 4.3 Сетка и отступы

- Контейнер `min(1120px, 92vw)`, вертикальный ритм на `--space: clamp(4rem, 10vh, 8rem)` между секциями.
- Карточки: CSS Grid `repeat(auto-fit, minmax(min(340px, 100%), 1fr))` + container queries внутри карточки.

## 5. Компоновка страницы (сверху вниз)

Порядок секций = порядок чтения резюме: сначала «кто», потом «путь», потом «что сделал на работе», потом «что делаю для души».

### 5.1 Hero — «Экран персонажа» (100svh, первый экран)
Первый экран отвечает на «кто это» мгновенно и в игровой форме:
- **Фон**: 3D-сцена на OGL — низкополигональное «поле» из светящихся частиц и линий с глубиной и туманом; камера медленно дрейфует, на десктопе отзывается на курсор параллаксом. Палитра из `--accent`/`--bg`.
- **Контент — карточка персонажа**:
  - моноширинный ярлык `~/samoy.love · character sheet`;
  - H1 — имя; строка класса: `Teamlead @ Почта Mail.ru`;
  - **строка статов** в моно (реальные цифры уточним): `LVL {лет в IT} · команда ×10 · {N} рабочих кейсов · {M} pet-проектов`;
  - одна строка самоиронии: `по вечерам — Go, игры и странные pet-проекты`.
- **Навигация-якоря** (закреплённая, компактная): Путь · Работа · Pet-проекты · Контакты — страница длинная, ориентация обязательна.
- Индикатор скролла внизу.

### 5.2 «Прокачка» — путь и игровое резюме
Сразу за hero, ядро резюме. Вертикальный таймлайн-«level path»:
- Линия **рисуется по мере скролла** (scroll-driven, чистый CSS), вехи зажигаются акцентным свечением при входе во вьюпорт.
- Вехи: **Школа → Универ → первая работа → Backend → Senior → Teamlead @ Почта Mail.ru** (точный список — от Алексея). Каждая веха:
  - год(ы) в моно, название этапа, 1–2 строки сути;
  - **интересный факт** — человеческая деталь, а не сухая строка резюме («первый код — …», «пришёл в Mail через …»);
  - **ачивки этапа** — маленькие иконки-чипы, «анлокнутые» на этом этапе.
- Рядом/ниже — **витрина достижений**: сетка ачивок в едином стиле (строгая иконка + название + подпись), обычные — циановая рамка, редкие — янтарная. Примеры категорий: образование, карьерные вехи, технологии, командные результаты, релизы pet-проектов. Hover — тултип с деталью.

### 5.3 «Основной квест» — рабочие проекты
Секционный ярлык: `// основной квест — Почта Mail.ru`. Реальные рабочие кейсы (контент — от Алексея; без NDA-нарушений):
- Две карточки рядом, по арку роста в каждой: схема продукта, бейдж арка («стажёр → senior»), **роль**, 2–4 строки описания, **результаты** (что можно публиковать), стек.
- Пока продукты не согласованы к публикации — вместо скриншотов схемы-заглушки с честной подписью прямо на картинке.
- Картинки lazy, с точными размерами (CLS 0).

### 5.4 «Сайд-квесты» — fun-pet-проекты
Секционный ярлык: `// сайд-квесты — делаю для души`. Карточки из `src/data/projects.json`:
- Скриншот/обложка, название, 1–2 строки, стек-теги, 1–3 **метрики-факта** («дифф-обновления, Blake3», «бинарный протокол, 19 типов событий», «офлайн-PWA, роутинг на клиенте»).
- Ссылки: «Открыть/Играть» (если задеплоен) и «Подробнее» → страница проекта.
- Hover (desktop): **3D-tilt на чистом CSS** (`perspective` + `rotateX/rotateY`, обложка на `translateZ` глубже) + свечение цветом проекта. Tap (mobile): tilt выключен, вся карточка — ссылка.

Стартовые три: **ChillHub** (Go-лаунчер: дифф-обновления, хеш-контроль, админка), **Hello Kitty Метро** (офлайн-PWA, Canvas-схема, Go-решатель layout), **Snakes** (мультиплеер 16 игроков, боты, бинарный WS-протокол).

### 5.5 Страницы проектов (`/projects/<slug>/`)
Для pet-проектов (и опционально рабочих кейсов):
- Генерируются Astro из JSON + markdown.
- Структура: обложка → что это → игровой цикл → инженерное → стек → ссылки на живой проект.
- **View Transitions**: обложка карточки «перелетает» в шапку страницы проекта — общий `transition:name` вида `cover-<slug>` на обоих изображениях. Роутер — `<ClientRouter />` (+5.5 КБ gzip).

> Плата за роутер: документ больше не перезагружается, поэтому скрипты
> компонентов инициализируются по `astro:page-load`, а 3D-сцена гасится по
> `astro:before-swap` — иначе она продолжала бы рисовать в выброшенный канвас
> и плодить WebGL-контексты. Это покрыто сквозным тестом.

### 5.6 Контакты + футер

## 6. Эффекты — «WOW, но умный»

| Уровень | Условие | Что включено |
|---|---|---|
| **Full** | desktop / мощный mobile, `prefers-reduced-motion: no-preference` | 3D-сцена hero (OGL), рисующийся таймлайн, заполнение полосы опыта, 3D-tilt карточек, scroll-reveal, перелёт обложки между страницами |
| **Lite** | слабое устройство (`hardwareConcurrency ≤ 4` или `deviceMemory ≤ 4`), экономия трафика | Вместо 3D — CSS-градиент с `@property`-анимацией hue; tilt выключен; scroll-reveal остаётся (он дешёвый) |
| **Static** | `prefers-reduced-motion: reduce` | Всё статично и видимо сразу, мгновенные переходы |

Правила:
- WebGL-канвас: rAF с паузой при `document.hidden` и вне вьюпорта; DPR-кап 1.5; деградация при `webglcontextlost`.
- Только `transform`/`opacity`/`filter` — ничто не двигает layout.
- 3D и анимации — внутри элементов, скелет неподвижен. Никакого скролл-хайджекинга.
- Контент никогда не «заперт» за анимацией: без JS и на Static-уровне видно всё.
- JS-бюджет: **< 25 КБ gzip** (факт: 1.0 КБ входной скрипт + 5.5 КБ роутер + 14.5 КБ чанк OGL по требованию).
- `prefers-reduced-motion` гасит и переходы страниц: `::view-transition-*` — отдельная от обычных `animation` ветка, её выключаем явно.

## 7. Производительность — бюджеты

| Метрика | Цель |
|---|---|
| LCP (mobile, 4G) | < 1.8 с |
| CLS | 0 |
| INP | < 100 мс |
| Вес первой загрузки | < 250 КБ (шрифты + hero-постер включительно) |
| Lighthouse (mobile) | 95+ по всем категориям |

Тактика: инлайн критического CSS, preload двух подмножеств Inter, ленивая загрузка обложек и схем, иммутабельный кэш `/_astro/`. Хостинг — свой сервер под nginx, выкатка через deploy-kit.

## 8. Мобильная версия

- Mobile-first; `100svh` для hero; `viewport-fit=cover` + `env(safe-area-inset-*)`.
- Строка статов hero переносится в 2 строки; навигация-якоря — компактный закреплённый бар.
- Таймлайн — одна колонка, линия слева; сетка ачивок — 3–4 в ряд мелкими чипами.
- Рабочие кейсы — вертикальные карточки (скрин сверху). Тач-цели ≥ 44px.
- 3D-сцена на мобиле: DPR 1, меньше частиц — или Lite-уровень.

## 9. Доступность

- Семантика: `header/main/section/article/footer`, один H1, логичная иерархия.
- Контраст ≥ 4.5:1; полная клавиатурная навигация, видимый `:focus-visible`.
- `prefers-reduced-motion` → Static; канвас `aria-hidden="true"`.
- Ачивки — настоящий текст, не только иконки (тултипы дублируются в разметке).

## 10. Данные — как добавлять контент

Всё контентное — в JSON/markdown, добавление = коммит:

- `src/data/profile.json` — имя, класс, статы hero, контакты.
- `src/data/timeline.json` — вехи пути: `{период, титул, текст, факт, achievements: [id]}`.
- `src/data/achievements.json` — ачивки: `{id, icon, title, note, rarity: "common"|"rare"}`.
- `src/data/work.json` — рабочие кейсы: `{title, role, period, text, results: [], stack: [], screens: []}`.
- `src/data/projects.json` — pet-проекты (пример ниже) + `src/content/projects/*.md` — длинные описания.

```json
{
  "slug": "snakes",
  "title": "Snakes",
  "tagline": "Мультиплеерный захват территории в браузере",
```

## 13. Что сознательно НЕ делаем

- Прелоадеры и заставки — мгновенное открытие и есть «вау».
- Мультяшную геймификацию: пиксель-арт, полоски HP, звуки — дешевит; игровая только структура подачи.
- Кастомный курсор, скролл-хайджекинг — мешают и устарели.
- Трекеры и куки-баннеры — отсутствие подчёркиваем в футере.
- CMS — JSON + git удобнее для одного разработчика.
